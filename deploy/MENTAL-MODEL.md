# 最终部署心智模型

## 1. 用户使用的是产品，计算由本机或远端提供

```text
本机模式：
  系统音频 → synesthesia-full 的采音与推理 → 本机悬浮字幕

远端算力模式：
  系统音频 → synesthesia-client → WebSocket → synesthesia-server
                ↑                         ↓
           本机悬浮字幕 ← 原文、译文与状态 ← 推理
```

`full` 是完整本机体验，`server` 提供计算能力，`client` 负责用户所在桌面的采音与展示。它们共享字幕行为和配置概念，但只交付各角色实际需要的依赖。

`full` 不要求用户自行启动独立服务端。内部如何复用服务逻辑，以及是否同时对外开放服务，由技术设计确定。

## 2. 构建目录、安装包、运行目录是三个对象

- **源码部署目录 `deploy/`**：保存可审阅的交付约定、模板和部署入口。
- **安装包**：一个固定版本、固定平台、固定角色的软件交付物。当前只有骨架预览。
- **运行目录**：用户实际启动程序的位置，包含程序和可变运行状态。

`payload/` 是准备放入运行目录的模板，不是已经安装好的产品。Rust 构建产物是打包输入；编译器、构建缓存与开发环境不是默认运行依赖。

## 3. 软件就绪不等于模型就绪

```text
软件文件存在并通过哈希校验
  → 后端和设备能初始化
  → 用户提供的模型兼容且能加载
  → 实际推理使用选定资源
  → 音频到双语字幕的完整验收通过
```

每一层独立记录结果。检测到显卡不等于已使用 GPU，模型加载成功不等于字幕质量或延迟合格。

全功能版和服务端需要识别与翻译模型；客户端不需要模型。模型文件大小不等于运行内存或显存占用。

## 4. 便携范围是应用状态集中，不是没有系统依赖

应用管理的配置、日志、模型、缓存、临时文件位于运行目录。系统驱动、窗口系统、音频权限、系统组件和驱动自身缓存仍由宿主管理。

启动器只为当前进程及其子进程设置必要环境。不能通过“便携”描述承诺零系统痕迹，也不能静默放宽系统权限。

移动到另一目录或电脑后，路径不能依赖原盘符；新的设备名称、硬件能力、架构、驱动和权限需要重新确认。

## 5. 一个目录负责一种产品和一个版本

推荐分别安装到 `synesthesia-full/`、`synesthesia-server/`、`synesthesia-client/`，不在安装时混用不同版本的程序或依赖。

运行目录中的 `.synesthesia-portable.json` 是安装器的管理标记与程序文件清单，不是产品配置。配置和模型是用户数据，重复安装不静默覆盖。

同版本重复安装优先做完整性检查。跨版本升级在新目录验证后迁移配置，用户可保留旧目录作为回退版本。

## 6. 算力选择与服务状态必须可见

服务器启动顺序为：检测硬件、选择后端、启用资源、加载模型、报告就绪、处理会话。监听端口或容器仍在运行不能单独作为推理就绪证明。

指定 GPU 后不得悄悄回退 CPU。任何允许的回退都应明确显示，默认策略由产品实现确认。自动选择设备也不能仅硬编码某台机器上的编号。

停止一个会话和停止整个服务具有不同作用。是否在会话停止后保留模型尚待确定；退出进程或容器时应释放其资源。

## 7. Docker 是服务端的一种交付方式

```text
桌面系统：synesthesia-client，采集当前电脑音频并显示悬浮窗
容器环境：synesthesia-server，接收音频并进行推理
宿主环境：向容器提供所需计算资源、驱动与网络条件
```

Docker 不自动取得客户端电脑的音频，也不在容器中显示该电脑上的悬浮窗。CPU 镜像和不同 GPU 后端的适用条件分别说明。容器化成功不代表所有宿主 GPU 均已验证。
