# 服务端容器交付

当前只提供编排与配置示例，没有 Dockerfile、可运行镜像或通过验证的容器服务。

容器中的 `synesthesia-server` 提供识别与翻译；桌面上的 `synesthesia-client` 采集音频、通过 WS 连接并显示悬浮字幕。桌面程序不通过该镜像安装。

## 目录和数据

| 容器对象 | 计划位置 | 所有权 |
| --- | --- | --- |
| 自主服务端程序与私有依赖 | 镜像内，由 Dockerfile 确定 | 镜像发行 |
| 服务配置 | `/app/config/settings.json` | 宿主配置，只读挂载 |
| 模型 | `/app/models` | 用户手动准备，只读挂载 |
| 后端缓存 | `/app/cache` | 独立持久卷 |
| 日志 | `/app/logs` | 独立持久卷 |
| 临时数据 | `/app/temp` | 容器临时空间 |

`server.example.json` 是配置草案，路径仅用于拟定容器契约。复制为正式配置前必须确认程序解析、监听端口、模型路径与运行权限。

## 编排草案

`compose.example.yaml` 要求显式提供真实的 `SYNESTHESIA_SERVER_IMAGE` 和外部数据目录。镜像入口必须定位配置并在容器内监听对应网络接口；此约定尚未实现。

拟定 WS 端口为容器 8765，可在宿主机映射为其他端口。模板只绑定宿主 `127.0.0.1`；局域网连接需要明确选择绑定地址并确认鉴权和访问控制。

CPU 基线是第一种待验证组合。GPU 按后端增加镜像与 Compose 配置，分别说明设备映射、驱动、运行库、权限和实际推理结果。模板没有 GPU 配置，不宣称 GPU 支持。

未来需要补齐：

- 固定基础镜像与程序版本的 Dockerfile。
- 非 root 运行用户和可写卷权限。
- 程序模型就绪检查；容器运行或端口监听不算推理就绪。
- 正常停止、会话清理和卷保留规则。
- CPU 与具体 GPU 后端的端到端验收。

停止容器不删除用户模型或外置配置。缓存和日志卷是否删除由用户明确选择；凭据不写入示例配置或镜像。
