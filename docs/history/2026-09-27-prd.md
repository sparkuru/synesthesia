## 1. 文档状态

- 日期：2026-09-27。
- 状态：MVP 产品决策已收敛，等待最终技术规划审阅；尚未实现或完成产品验收。
- 产品名称：`synesthesia`。

- “已确认”表示用户明确提出的需求；“建议”表示评估中提出的方案；“待定”表示尚未确认或完成验证的事项。

## 2. 背景与目标

产品的核心使用链路是采集系统播放音频，进行语音识别与翻译，在置顶悬浮窗口显示双语字幕。桌面应用负责音频、会话与字幕交互，计算能力可部署在用户本机或另一台设备上。

本项目独立设计实现一个轻量桌面实时字幕工具，提供本机全功能与远程算力两种使用方式。用户可以直接使用自己的硬件，也可以由另一台设备提供计算能力。

### 2.1 已确认目标

1. 支持系统音频的实时识别、翻译与悬浮字幕展示。
2. 前台以轻量桌面应用为主，支持置顶悬浮字幕。
3. 提供 `synesthesia-full`、`synesthesia-server`、`synesthesia-client` 三种产品形态。
4. 支持客户端/服务端结构，使用 WebSocket 连接算力与前台。
5. 支持跨平台；Windows 原生交付，Linux 服务端另提供可选 Docker 部署能力。
6. 自身程序具备独立应用逻辑、完整源码和构建流程。

### 2.2 目标体验

用户播放外语视频、直播或其他有语音的内容时，在当前桌面中看到原文与译文，无需反复切换到独立转录页面。字幕处理可以在本机完成，也可以交给用户配置的远端服务。

已确认首版语言验收范围为英语、日语识别并翻译为简体中文；更多语种后续扩展。

### 2.3 成功标准

- 本机模式能够完成采音、识别、翻译、显示的完整闭环。
- 客户端能够连接服务端并获得实时原文和译文，客户端不必安装推理模型。
- 用户能够明确知道当前使用的设备、计算后端和服务状态。
- 字幕更新不长期积压，不因译文较慢而阻塞已有原文的展示。
- 运行、停止、断线和退出行为可预测，相关资源能够释放。
- 支持范围以真实设备验证为准，不用框架宣称的跨平台能力代替验收。

## 3. 用户与使用场景

| 场景 | 用户诉求 | 产品形态 |
| --- | --- | --- |
| 本机观看 | 一台设备上采音、推理并显示字幕 | `synesthesia-full` |
| 轻量设备连接算力设备 | 当前设备负责采音与展示，另一台设备负责计算 | `synesthesia-client` + `synesthesia-server` |
| 家庭或个人局域网部署 | 长期开启算力服务，按需接入客户端 | `synesthesia-server` |
| Linux 容器化运行后台 | 固定服务运行环境，独立管理模型与配置 | 可选 Docker 中的 `synesthesia-server` |

已确认首版聚焦个人使用和局域网单路系统音频。多客户端连接不等同于多路音频同时满足实时推理要求，后者属于后续范围，需要单独定义容量并验证。

## 4. 产品形态

### 4.1 `synesthesia-full`：本机全功能版

**已确认定位：** 集成全流程，直接利用用户本机硬件，同时提供算力与前台。

功能边界：

- 识别本机计算资源与音频设备。
- 配置并启用支持的推理资源，加载所需模型。
- 采集本机系统播放音频。
- 实时识别、翻译并显示悬浮字幕。
- 提供设备、语言、字幕样式与运行状态设置。
- 启动、停止、退出时管理音频、模型和推理资源生命周期。

用户不需要另外部署独立服务端，即可完成字幕处理。已确认首版 full 只做本机闭环，不对外提供算力服务；远程算力由独立 server 提供。

### 4.2 `synesthesia-server`：算力服务端

**已确认定位：** 识别硬件资源，启用硬件资源，开启服务等待客户端连接，并提供计算能力。

功能边界：

- 检测 CPU、支持的 GPU、可用后端与相关运行条件。
- 根据配置选择设备与后端，初始化识别和翻译能力。
- 提供服务入口，接收客户端发送的音频与会话控制请求。
- 向对应客户端输出识别、翻译与运行状态。
- 维护客户端会话、语言设置和翻译上下文的隔离。
- 提供模型加载、就绪、运行、过载和错误状态。
- 支持无桌面环境运行；Windows 使用原生服务端，Linux 服务端另提供可选 Docker 部署。

服务端不负责捕获远端客户端所在电脑的系统音频，也不承担该电脑上的悬浮窗口显示。

### 4.3 `synesthesia-client`：桌面客户端

**已确认定位：** 服务端的配套应用，在客户端设备上启动悬浮窗并连接算力。

为完成端到端链路，客户端还应承担本机采音：

- 选择并采集本机系统播放音频。
- 配置服务地址，建立连接并控制字幕会话。
- 向服务端发送音频，接收字幕与状态。
- 在桌面悬浮窗显示原文和译文。
- 提供连接状态、音频设备、语言和字幕样式设置。
- 明确反馈断线、服务未就绪、音频不可用等问题。

客户端不承担模型推理；无 GPU 的设备也应能作为客户端使用。

## 5. 核心功能需求

### FR-01 系统音频采集

- 全功能版和客户端必须支持采集系统播放音频。
- 能枚举可用音频输出，并支持选择默认或指定设备。
- 默认设备切换、设备断开、静音和播放恢复时应有明确行为。
- 音频设备切换不应触发不必要的模型重新加载。
- 应显示足以判断采音是否有效的状态，如设备名称、音量活动或错误提示。
- 不支持的平台或设备组合应明确提示，不能用麦克风采集冒充系统音频采集。
- 麦克风、音频文件和仅浏览器标签页采集属于后续可选输入，首版是否纳入待定。

### FR-02 硬件资源检测与启用

- 全功能版和服务端应区分“检测到硬件”“后端可用”“模型加载完成”“实际使用该硬件”四种状态。
- 支持查看可用设备，并根据配置选择计算资源。
- CPU 与 GPU 的支持范围按平台、后端和设备组合说明。
- 设备或模型不可用时提供可理解的原因。
- 已确认首轮优先使用 RX 9070 XT，先验证 Vulkan 路线；CPU 可由用户手动选择。GPU 初始化或推理失败时明确报错，不静默回退至 CPU，不继续显示未实际使用的 GPU 状态。
- 用户指定资源后，应能通过运行诊断确认实际推理使用的设备。

### FR-03 实时识别与字幕状态

- 识别结果区分可更新的草稿字幕与已确认的定稿字幕。
- 同一句草稿更新应替换原内容，不连续追加成重复字幕。
- 定稿应覆盖该句草稿，且不能被迟到的草稿重新覆盖。
- 字幕应具有可关联的身份与音频时间信息，便于识别、翻译和显示对应。
- 静音、连续讲话、长句和语句切分应有可测试的行为。
- 已确认首版由用户手动选择英语或日语作为源语言，不自动检测；更换语言在新会话边界生效，清理旧输入与翻译上下文。自动语言检测留作后续。

### FR-04 翻译

- 支持目标语言选择和原文/译文展示；已确认简体中文为首版验收目标语言。
- 在双语/仅原文模式下，已有原文应及时显示，不等待翻译完成。
- 译文必须关联对应语句和文本版本，过期译文不能覆盖较新的字幕。
- 翻译失败不能阻止识别结果继续显示，应反馈状态并保留原文。
- 翻译上下文按会话隔离，避免不同客户端或重新开始的会话串用内容。
- 已确认首版草稿立即显示原文，只对定稿字幕发起翻译；不等待译文才显示已有原文。草稿翻译作为后续可配置能力，在性能与字幕稳定性验证后启用。
- 已确认默认双语显示，原文在上、对应译文在下；保留最近 3 句（含当前草稿或定稿），长句自动换行。每句的原文和译文计为一组，不按换行后的视觉行数计数。
- 支持切换仅原文/仅译文显示；切换仅影响呈现，不重新识别或翻译。仅译文模式等待定稿翻译，不展示原文草稿，未完成或失败时提供状态。

### FR-05 轻量悬浮字幕窗

- 全功能版和客户端提供置顶悬浮字幕窗。
- 建议支持无边框、透明或半透明背景、位置调整和窗口缩放。
- 已确认默认调整模式且不穿透；观看模式支持鼠标穿透，调整模式允许拖动与操作。
- 托盘提供观看/调整切换、打开设置、停止字幕和退出；穿透后通过托盘恢复操作，托盘不可用时禁止进入无法恢复的穿透状态。
- 关闭设置窗只隐藏，不停止字幕或退出；全局快捷键、开机启动和自动更新留作后续。
- 支持字幕字体、字号、颜色、背景透明度和显示句数设置；默认最近 3 句。
- 中英文和目标语言字符应正常显示；长字幕应合理换行。
- 应验证多屏移动、不同缩放比例和高 DPI 显示。
- 运行状态应易于查看，复杂诊断信息放在适当的设置或诊断入口。
- 全屏应用、独占全屏和各平台窗口层级的覆盖行为必须实测，不能把“置顶”宣传成覆盖一切窗口。

### FR-06 WebSocket 与远程会话

- 客户端手动配置服务地址与共享令牌并连接服务端；首版不做自动服务发现。
- 支持音频上传、会话开始/停止、字幕返回和错误/状态反馈。
- 客户端格式与服务端要求不兼容时，应明确拒绝或提示。
- 同一会话中的音频顺序、字幕替换和定稿状态应一致。
- 已确认断线自动重连时创建新会话，丢弃旧音频与旧翻译上下文；不补播断线期间音频、不复用旧会话结果，不能重复显示已确认字幕。
- 音频和字幕缓冲必须有上限；过载时应反馈，避免延迟无限增长。
- 已确认首版共享令牌鉴权，仅用于本机或受控局域网普通 WS；普通 `ws` 不加密音频、字幕或令牌。TLS/WSS 与公网部署留作后续。
- 服务端在接收会话音频前完成鉴权；无令牌或令牌错误明确拒绝，不将令牌写入 URL、日志、示例或发行包。

### FR-07 生命周期与诊断

- 已确认停止字幕会话与退出应用是不同动作：计算端停止会话时保留已加载模型，退出应用时卸载模型并释放资源。客户端没有模型保留行为。
- 推理初始化期间显示加载状态，准备完成后显示就绪。
- 停止会话后停止采音/上传、取消会话推理与翻译任务并清理队列和上下文；保留的模型及受管理引擎可以继续占用内存/显存，但不得继续处理已停止会话。
- 退出应用后释放所属采音、连接、模型、推理任务和辅助进程，无所属残留任务或子进程。
- 错误信息能区分采音、连接、模型和计算后端问题。
- 应提供延迟、缓冲积压和实际设备使用情况的诊断能力。
- 已确认首版不保存原始音频、字幕正文或完整会话记录；音频与字幕仅用于当前会话内存处理，不写入日志、缓存或临时文件。
- 仅保存诊断日志，不含音频、字幕正文或连接令牌；每个运行目录内应用及受管理引擎的诊断日志轮转总量上限为 20 MiB，超限淘汰最旧日志。历史字幕回看与内容导出留作后续。

## 6. 跨平台与部署要求

### 6.1 桌面平台

目标覆盖 Windows、Linux 和 macOS。平台支持包括真实的系统音频采集、悬浮窗与显示行为，不仅是能够编译启动。

| 平台 | 需要重点验证的能力 | 当前状态 |
| --- | --- | --- |
| Windows | 系统播放音频采集、设备切换、透明置顶窗、鼠标穿透 | 已确认首版支持目标为 Windows 10/11 x64；采音与版本兼容尚未实现/验收 |
| Linux | 音频服务适配、X11/Wayland 窗口行为、GPU 后端 | 待验证；需分别说明显示协议支持范围 |
| macOS | 系统音频捕获权限、最低系统版本、透明悬浮窗、计算后端 | 待验证 |

已确认先形成 Windows 10/11 x64 桌面闭环，不把首轮验收机的 build 26100 设为最低版本；Linux/macOS 桌面后续支持。Windows 两代系统分别验证，不能用单台 Windows 11 的结果代替 Windows 10 验收。
Windows 的 full/server/client 均使用原生程序，用户安装、运行及 Windows 实机验证不依赖 Docker、Docker Desktop 或 WSL。Linux Docker 服务端是独立的可选部署路线，不代表 Linux 桌面已支持。

### 6.2 Docker

- 已确认 Docker 仅作为 Linux 服务端的可选部署方式；Windows 的三个角色均原生运行，安装与运行不依赖 Docker。
- 桌面采音和悬浮窗在用户桌面系统中运行，不要求用户为桌面功能安装容器环境。
- 模型、配置和需要保留的数据应能独立管理，不要求模型固定打入镜像。
- 提供可检查的启动、就绪、停止和诊断行为。
- 首版保留 Linux Docker CPU 服务端基线；容器 GPU 支持属于后续范围。
- GPU 支持需说明宿主机系统、驱动、设备和运行条件；不承诺一个镜像覆盖所有 GPU。
- Windows 原生 GPU 验收不作为 Linux Docker GPU 证据；AMD 等容器 GPU 组合必须另行验证。
- 首版不交付 Windows Docker 运行方案，也不以 Windows Docker GPU 能力作为验收条件。

### 6.3 软件安装包与便携目录

- 按角色、版本、平台和架构交付自主构建的软件，不要求用户具备开发工具链。
- 程序、私有依赖与配置、模型、日志、缓存和临时文件分开管理；用户状态尽量位于便携运行目录。
- 安装目标可配置，整体目录移动后不依赖旧盘符；卸载前退出程序，再删除对应运行目录。
- 当前默认部署约定不下载、复制或打包模型，模型由用户在计算端手动提供；客户端无需模型。
- 支持软件离线缓存、固定版本与 SHA256 校验；拒绝错误资产和未管理的非空目标目录。
- 安装先在临时目录组装并校验，再发布；重复安装保留用户配置和模型，跨版本升级使用新目录。
- 默认不修改系统全局 PATH 或安装系统级开发环境，GPU 驱动、音频权限等外部条件单独说明。
- 交付结构与当前完成状态见 [deploy/README.md](deploy/README.md)。部署骨架不能被宣传为已完成的软件发行版。

## 7. 性能与质量要求

| 维度 | 要求 | 验证方式 |
| --- | --- | --- |
| 原文及时性 | 翻译耗时不阻塞原文显示 | 分别记录草稿、定稿与译文出现时间 |
| 实时处理能力 | 连续输入时积压不持续增长 | 长时间输入并观察积压与实时处理速率 |
| 字幕一致性 | 草稿可替换，定稿稳定，不出现迟到结果覆盖 | 短句、长句、重复事件和延迟结果场景 |
| 翻译质量 | 译文与对应原文一致，上下文不串会话 | 初期目标语种与真实视频样本评估 |
| 桌面开销 | 轻量窗口的空闲与更新开销可测量、可解释 | 在关闭本地推理或使用远端时单独测量前台 |
| 稳定性 | 静音、设备切换、网络异常和停止退出有明确行为 | 真实设备与故障场景验证 |
| 资源释放 | 退出后无所属残留采音、连接、推理任务或子进程 | 退出后的运行状态检查 |
| 会话隔离 | 客户端间不混用字幕、语言和翻译上下文 | 多会话隔离验证 |
| 数据保留 | 不保存音频/字幕内容，诊断日志不含正文或令牌且总量不超过 20 MiB | 检查运行目录与引擎输出、连续写入触发轮转并重启复核 |

已确认首轮固定英语、日语各 10 分钟清晰单人语音样本，覆盖短句、长句和静音；多人对白与背景音乐作为补充测试，强噪声和重叠语音不设首版质量硬门槛。样本来源、文件与参考文本由兼容子任务固定，不用临时挑选的片段代替可复测基准。

首轮验收基准已通过 SSH 只读检查确认：Windows 11 IoT 企业版 LTSC（build 26100）、Ryzen 9 7950X（16 核 / 32 线程）、64 GiB 安装内存、Radeon RX 9070 XT（驱动报告约 15.92 GiB 显存）。Vulkan 工具可枚举独显；模型加载与实际 GPU 推理尚未验证。

已确认分阶段验收：连续运行 60 分钟无崩溃、积压不持续增长；先在指定模型、RX 9070 XT 与固定样本上取得真实基准，再与用户审阅并锁定文本质量、草稿/定稿/译文延迟和资源数值门槛，达标后才能发布。数值暂缓不代表任意实测结果都能通过；单路容量已确认，不另承诺多路实时能力。模型文件大小不等于运行内存或显存需求。

## 8. 首版范围与后续范围

首版产品形态、平台、输入容量、连接方式、部署边界、翻译时机、托盘交互、字幕呈现、数据保留、样本范围与分阶段验收策略已确认；具体质量/性能数值在真实基准后审阅，实施以最终规划批准为起点。

### 8.1 首版：单路闭环

- 原生 full/server/client 三种产品形态具备明确的功能边界；Windows 安装与运行不依赖 Docker。
- 首发桌面支持目标为 Windows 10/11 x64，两个系统分别验证；Linux/macOS 后续支持。
- 单路系统播放音频采集、原文草稿/定稿与双语悬浮展示；已确认草稿立即显示原文，定稿后再翻译。
- 已确认语言验收范围：手动选择英语或日语 → 简体中文；更多语种后续扩展。
- 本机全功能使用，以及一对客户端/服务端的受控局域网 WS 使用。
- full 仅本机，不对外服务；计算端停止字幕会话保留模型，退出应用卸载模型并清理所属资源。
- 默认悬浮窗不穿透，托盘切换观看/调整模式并提供设置、停止和退出；关闭设置窗只隐藏。
- 手填地址与共享令牌；断线自动重连新建会话，丢弃旧音频与上下文；首版普通 WS，TLS 与公网部署后续。
- 可观察的设备使用、连接状态、错误与积压。
- 不保存音频和字幕记录；仅保留不含正文/令牌、总量上限 20 MiB 的轮转诊断日志。
- 已确认原生计算优先 RX 9070 XT / Vulkan 兼容验证，CPU 可手动选择，GPU 失败不静默回退。
- 可选 Linux 服务端 Docker CPU 基线，与 Windows 原生交付和实机验收分开。

### 8.2 后续：部署与平台扩展

- 更多 GPU 的原生推理与目标 GPU 的 Docker 推理验证；首轮 RX 9070 XT 原生验证已纳入资源策略。
- Linux 与 macOS 桌面采集和悬浮行为。
- 草稿翻译与更丰富的语言支持。
- 自动源语言检测。
- 全局快捷键、开机启动与自动更新。
- 历史字幕回看、音频记录与字幕内容导出。
- 多个显示端、Web/OBS 字幕展示、麦克风或文件输入。
- 在容量验证后支持多路实时音频。

### 8.3 当前非目标

- 自行训练语音识别或翻译基础模型。
- 为追求全 Rust 而重写成熟推理引擎的全部计算实现。
- 第一版即覆盖所有操作系统版本、GPU 和驱动组合。
- 公网多租户、商业计费、账号体系或大规模服务集群。
- 承诺普通置顶窗口能够覆盖所有独占全屏应用。

## 9. 实现约束与暂定选型

- 自身应用逻辑独立设计实现，发行程序来自本项目源码构建。
- Rust 是当前讨论的实现方向，尚未完成最终技术定稿。
- egui/eframe 是轻量悬浮前台的首选候选，需通过真实窗口原型验证后确认。
- CrispASR、llama.cpp 及相应识别/翻译模型可以作为初期候选，尚未锁定新项目的最终依赖组合。
- 无论使用何种 GUI 或引擎，采音、字幕行为、性能和平台支持都应满足本文的产品验收要求。
- 自身代码、第三方依赖与模型的许可分别核对；独立实现自身应用逻辑不免除所使用或分发组件的许可义务。
- 本文不锁定 WS 消息格式、模块划分、进程模型、推理调用方式或容器编排细节，这些应在技术设计中确定。

## 10. 验收标准

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| AC-01 | 本机全功能启动 | 能识别可用资源，加载模型并启动采音、识别、翻译与悬浮展示 |
| AC-02 | 服务端启动 | 能检测和初始化配置的计算资源，在准备完成后接受客户端会话 |
| AC-03 | 客户端使用 | 在无推理模型的客户端设备上采音，以手填地址与正确共享令牌连接服务端并显示字幕；鉴权失败明确拒绝 |
| AC-04 | 字幕草稿与定稿 | 同句草稿替换显示，定稿后不重复追加、不被迟到草稿覆盖 |
| AC-05 | 译文较慢或失败 | 双语/仅原文模式中草稿原文立即显示，只有定稿发起翻译；译文关联正确版本，较慢或失败不阻止原文处理，失败有反馈；仅译文模式不展示原文、明确显示翻译状态 |
| AC-06 | 静音与长句 | 静音不持续产生无关字幕，语句切分与长句定稿行为符合定义 |
| AC-07 | 音频设备切换 | 能继续采音或给出明确错误，旧设备的积压不污染新输入 |
| AC-08 | 悬浮窗操作 | 默认不穿透，置顶、透明度、拖动、缩放和观看/调整模式按支持范围工作；托盘可恢复调整、打开设置、停止和退出，关闭设置只隐藏；托盘不可用时不会进入无法恢复的穿透状态 |
| AC-09 | 字体与多屏 | 默认原文在上译文在下、显示最近 3 句（含当前句），长句换行不拆分语句组；可切双语/仅原文/仅译文且不重复推理。中文及目标语种正常显示，窗口在已声明支持的多屏/DPI 场景可用 |
| AC-10 | 连接中断与重连 | 断线状态明确、可取消自动重连；成功重连新建会话并丢弃旧音频/上下文，不混用旧结果或补播旧音频 |
| AC-11 | 计算过载 | 缓冲有界且有反馈，不产生无限增长的延迟 |
| AC-12 | 可选 Linux Docker 服务端 | 在声明的 Linux 环境中可启动、检查就绪、连接客户端并正常停止；Windows 三角色无 Docker 依赖 |
| AC-13 | 指定 GPU | 首轮诊断确认实际使用 RX 9070 XT；GPU 失败明确报错、不静默回退，手动选择 CPU 后诊断反映 CPU |
| AC-14 | 停止与退出 | 停止会话后无该会话残留采音/上传/推理/翻译任务，保留模型但不处理旧会话；恢复可复用模型。退出应用后模型及所属任务/辅助进程全部释放 |
| AC-15 | 多会话隔离 | 不同会话的字幕、语言配置与翻译上下文互不污染 |

## 11. 技术验证与发布前门槛

1. Windows 10/11 x64 兼容性技术验证与测试环境；支持范围已确认，不限定 build 26100。Linux/macOS 已确定为后续支持，后续 Linux 的 X11/Wayland 范围另行确认。
2. 固定英日各 10 分钟清晰单人语音样本的来源、文件与参考文本；样本范围与手动源语言已确认，复杂场景作补充测试，自动检测留作后续。
3. RX 9070 XT / Vulkan 的实际模型推理兼容性与引擎设备标识映射；GPU 优先、CPU 手动选择和失败不静默回退的策略已确认。
4. 指定模型的发行来源/revision/许可、引擎兼容和额外 VAD 资产，以及离线安装/包完整性实测；模型手动提供与不默认打包/下载的边界已确认。
5. 真实基准后的文本质量、延迟及资源数值审阅与达标验证；连续运行 60 分钟无崩溃/无持续积压、单路与分阶段发布策略已确认，不将暂缓数值误作产品验收完成。
6. 字幕呈现的真实窗口验收；默认双语、原文上译文下、最近 3 句及单语切换已确认，长句自动换行；草稿翻译留作后续。
7. 共享令牌生成/配置入口与握手鉴权的具体实现；手填地址、共享令牌、局域网普通 WS 与新会话重连策略已确认，服务发现及 TLS/公网部署不纳入首版。
8. 引擎取消/回收能力及异常退出的技术验证；full 仅本机、停止会话保留模型、退出应用彻底释放的产品策略已确认。
9. 托盘与穿透恢复的真实窗口验证；默认不穿透、托盘控制与关闭设置仅隐藏已确认，全局快捷键、开机启动及自动更新留作后续。
10. 验证首版不保存音频/字幕内容及诊断日志脱敏、20 MiB 总量轮转；数据保留策略已确认。
