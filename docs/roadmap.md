# 开发路线

以 [PRD](../prd.md) 为验收依据，已有实现见 [状态](status.md)。每步留下可单独运行和回退的版本，支持矩阵只列真实通过的组合。

## R0：正式仓库基础（已完成）

落地 PRD、架构、状态、schema 2、统一 CLI、纯呈现投影、配置示例与全工程检查。正式入口默认构建，所有 workspace 成员继续参加质量检查。交付工程基础，不宣称实时应用完成。

## R1：麦克风 + Fun-ASR + 原文透明字幕

详细规划见 [R1 task](../.trellis/tasks/11-02-r1-microphone-fun-asr/prd.md)，由 [新版父计划](../.trellis/tasks/11-02-desktop-caption-pipeline/prd.md) 协调。首个真实验收平台已由用户确认为 Windows 11 x64；当前为 planning，尚未启动实现。R2–R5 仅保留路线，阶段开始前再详细建任务和审阅。

将 Python 已验证的使用体验转为 Rust 第一条可用链路：

- 实现麦克风采集、云连接、握手后采音、增量结果和有界收尾。
- 建立独立识别接口；不要求本地模型或翻译就绪。
- 实现真实透明置顶窗口、字号、视觉行数、设置恢复与可见错误。
- 对照草稿替换、清屏防复活、显式重新开始、Stop 最后一行与退出释放。

验收指定平台上的真实麦克风、服务和窗口；仅在用户提供本机密钥时进行实际云调用。设备、网络和主观可读性与无设备 CI 区分。

## R2：系统音频

复用已有 Windows WASAPI 回环和规范化，对接同一识别与字幕 UI。切换、断开或默认设备变化采用新输入身份，不混旧队列。

验收受控播放、默认/指定设备、静音、切换、过载和停止，确认没有改采麦克风。Windows 版本分别记录证据。

## R3：本地 ASR

拆分旧双模型 NativeInference 的识别生命周期，复用固定引擎/模型与 GPU 身份验证。翻译关闭不加载翻译模型；不静默回退 CPU 或云服务。

验收相同采音和显示切换到本地识别，断网可运行；测量质量、延迟、资源，以及取消、模型复用和退出。

## R4：可选翻译

提取独立翻译适配器，处理定稿与原文版本匹配；慢任务、错误和旧结果不阻塞原文。明确关闭/等待/完成/失败状态，显示模式只影响呈现。

验收本地和云 ASR 分别与翻译开/关组合，以及版本匹配与上下文隔离。

## R5：发行和扩展

声明支持的组合持续运行 60 分钟，审阅并锁定质量/延迟/资源指标，交付原生包。随后增加其他平台、服务、托盘、穿透、自动重连和远程计算。

旧 WS、打包任务和部署资料可复用，但应依新 PRD 重建实施任务，不原样继续执行旧方案。
