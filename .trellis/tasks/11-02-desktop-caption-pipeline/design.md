# 交付设计与迁移边界

## 架构依据

沿用 [现行架构](../../../docs/architecture.md)：core 拥有身份/字幕状态与预算，audio、识别适配器、可选翻译和 desktop 连接同一管线。原生资源由适配层拥有，正式应用负责实际编排。当前没有完整运行时；本规划不预建空模块。

R1 首个平台由用户确认为 Windows 11 x64；其 [详细设计](../11-02-r1-microphone-fun-asr/design.md) 独立于旧 full/server/client 拓扑。R2 接系统采音，R3 接独立本地识别，R4 接翻译，R5 做组合与发行验收。

## 复用与重新验收

| 旧成果 | 新计划如何使用 | 不继承的结论 |
| --- | --- | --- |
| C1 配置/身份/reducer/诊断/codec | 复用纯逻辑与测试，显式迁移运行策略 | 旧 schema 1 与 WS v1 不等于云服务协议或 schema 2 运行时 |
| C3 WASAPI/规范化 | 规范化可供 R1 麦克风适配；回环主体在 R2 接线 | 回环实测不证明麦克风，也不证明新入口已集成 |
| C2 本地进程/原生 helper | 在 R3/R4 分拆后复用 | 短样本不证明质量、长时或完整取消；R1 不依赖它 |
| C5 UI 研究 | 作为窗口技术原型的候选输入 | 不继承旧框架、托盘/穿透或三句默认的批准 |
| C4/C6/C7 旧计划与部署骨架 | 留作远程计算/发行阶段参考 | 不构成已实现服务、安装包或新阶段启动授权 |

## 计划与运行回退

各阶段必须保持之前已经验收的组合与旧兼容接口；有行为变化时更新实际源码规范及回归测试。真实后端/设备不可用时保留安全错误，不回退到其他服务、设备或本地模型。阶段实现失败可回到前一个工作提交，不删除历史材料或自动恢复旧产品计划。

当前只是父/子规划。没有建立自动串行开发授权或 mainline；R1 最终计划确认后才能 start，后续阶段到达时再详细设计并审阅。
