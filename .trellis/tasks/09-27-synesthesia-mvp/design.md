# synesthesia MVP 技术设计草案

状态：approved / implementation-in-progress。用户已在最终摘要后要求开始实现；候选后端与设备仍需按计划实测，不代表已完成实现或平台验证。
需求依据：[任务 PRD](prd.md)、[产品 PRD](../../../prd.md)、[证据记录](research/evidence.md)。
产品选择仍见任务 PRD 的决策清单；依赖版本在验证后固定，不以 `latest` 发布。

## 1. 模块与依赖方向

建议采用 Rust workspace，自身应用逻辑独立实现；不重写基础推理引擎。
下列名称为计划模块，仓库当前没有这些源码或 Cargo manifest。

| 计划模块 | 职责 | 禁止依赖 |
| --- | --- | --- |
| `core` | 字幕 reducer、会话状态、类型化配置、错误分类、队列预算 | GUI、平台采音、特定引擎 |
| `protocol` | WS 消息、音频帧封装、版本协商、解码与边界校验 | GUI、推理实现 |
| `audio` | 平台系统输出采集、设备枚举、下混与重采样 | 模型管理 |
| `inference` | ASR/翻译适配、模型与计算设备生命周期 | 窗口与系统采音 |
| `session` | 调度音频、ASR、翻译、取消、背压与诊断 | GUI |
| `server` | 无桌面服务、WS、就绪与连接管理 | 桌面采集与 GUI |
| `desktop` | 设置窗、悬浮窗、字幕视图与恢复操作 | 特定推理引擎 |
| 三个产品入口 | `full` 组合本机链路；`server` 组合算力服务；`client` 组合采音与远端连接 | 入口之间互相调用 |

`client` 的依赖图和安装包不得包含 `inference` 或模型；`server` 不引入 `audio` 的桌面实现和 `desktop`。
`full` 与 `server` 共用计算与会话逻辑；`full` 与 `client` 共用采音、字幕 reducer 与窗口逻辑。
本机采用进程内事件接口；远程将相同领域事件编码成 WS 消息，避免维护两套字幕语义。
已确认 full 只做本机闭环，不启动对外算力服务；对外 WS 由独立 server 提供。计算适配器若使用私有本机服务，仅绑定回环，不因共享模块而开放局域网监听。
已批准首版只处理单路实时系统音频；本机 full 与一对 client/server 都必须完成闭环。

## 2. 数据流与执行边界

```text
system output → capture → normalize PCM → bounded audio queue
  full:   local session ───────────────────────────┐
  client: WS → server session ─────────────────────┤
                                                 ↓
                    ASR → source event → subtitle reducer → overlay
                     └→ final translation queue → translation event ─┘
```

窗口线程只读取状态快照并处理交互，不执行采音等待、模型加载、网络阻塞或推理。
采音回调只完成有界写入；重采样和推理在工作线程/异步任务执行。
ASR 与翻译分别调度，翻译耗时不阻塞原文事件发送。实际硬件是否允许并行由兼容实验确认。

计算适配器提供 initialize / accept-audio / events / cancel / shutdown 语义。
建议先验证受管理的私有辅助进程：CrispASR PCM stdin + JSONL stdout；llama.cpp 私有本机服务或等效可取消接口。
不将上游的 WS 格式直接当作 synesthesia 协议。适配层检查输出格式并转换为自身事件。
辅助进程仅由拥有它的应用启动与清理；内部端口只绑定回环，输出和队列有界。
若上游退出、加载状态或取消能力无法满足契约，先记录实验结果，再评估 FFI；不提前承诺进程方案已可用。

## 3. 音频契约

候选规范化输入：16 kHz、单声道、signed PCM16 little-endian；实际格式在 ASR 实验后固定。
平台采集保留原始设备格式，由 `audio` 层统一转换；禁止仅改采样率标签而不重采样。
每帧携带 `session_id`、`input_generation`、`seq`、`start_sample`、`sample_count`。
时间使用会话内音频样本偏移，避免混用客户端与服务器墙上时钟。
帧大小、最大消息字节数与队列累计音频时长都是显式技术预算；C1 固定初始有界值，C2/C4 结合实测调整并同步消费者，遵守后续批准的延迟/资源发布门槛。

默认设备跟随与指定设备锁定是两种明确模式。切换时停止旧输入，递增 `input_generation`，
取消旧输入未完成任务并建立新采音流；保留可复用模型，不让旧设备的结果写入新字幕。
设备不存在或权限失败时返回采音错误；不自动改采麦克风。
静音由活动检测/VAD 与 ASR 实验共同验证；额外 VAD 模型需登记来源、许可与用户获取步骤。

## 4. 字幕状态与翻译一致性

语句身份：`(session_id, input_generation, utterance_id)`。
原文事件含 `revision`、`phase=draft|final`、`text`、`start_sample`、`end_sample`。
revision 由会话适配器单调分配；不能直接假设上游包含该字段。

Reducer 规则：

1. 当前会话或输入代际不匹配的事件丢弃。
2. 同一句较高 revision 草稿替换显示；重复或迟到事件不追加历史。
3. final 成为终态；任何迟到草稿不能覆盖它。重复 final 幂等处理。
4. 翻译以同一身份和 `source_revision` 定位，仅匹配当前原文版本时写入。
5. 翻译失败标记该句状态并保留原文；不终止 ASR。
6. 可见历史有界；已淘汰语句的译文不得重新插入窗口。
7. 语句 ID 单调生成，维护终结/淘汰水位，避免为防重复而无限保存所有旧 ID。

已确认草稿原文即时发布，翻译只接收 final；上下文限于同会话已确认语句，由任务预算控制。
草稿更新不得创建翻译任务；重复 final 幂等处理，不重复排队翻译。原文事件先发布，译文独立异步返回。
翻译较慢、超时或失败时保留原文与该句翻译状态，不阻塞后续 ASR；取消会话后迟到译文不能重新写入字幕。
源/目标语言改变需在清晰会话边界应用，不修改已经提交的语句。
长句需显式时长上限与定稿策略；上游默认参数是实验起点，不是本项目延迟承诺。

## 5. WS v1 协议提案

文本控制/事件使用 JSON；音频使用二进制帧。序列化入口统一校验，业务层使用已解码类型。
控制消息包含 `protocol_version`、`type`、`request_id`；会话建立后携带服务分配的 `session_id`。

| 方向 | 消息 | 关键行为 |
| --- | --- | --- |
| 双向 | `hello` / `hello_ack` | 协议版本、音频格式、语言与容量能力；不兼容明确拒绝 |
| 客户端→服务端 | `session_start` | 申请会话与语言配置；服务未就绪/满载时拒绝 |
| 服务端→客户端 | `session_started` | 分配身份、协商帧与队列预算；此后才能上传音频 |
| 客户端→服务端 | binary audio | 固定版本头 + 会话/代际/序号/样本范围 + PCM 载荷 |
| 服务端→客户端 | `source` / `translation` | 遵循第 4 节语句身份、revision 与终态规则 |
| 服务端→客户端 | `status` / `error` | 状态、实际计算设备、过载或失败原因；无敏感原文 |
| 双向 | `session_stop` / `session_stopped` | 停采、取消任务、清队列、释放会话资源 |
| 双向 | WS ping/pong | 活性与超时检查；不等同于模型就绪 |

二进制头的具体字节布局、枚举值、错误码与 golden fixtures 在协议子任务定稿。
校验消息上限、格式、样本数、音频序号、会话归属和合法状态，拒绝畸形帧。
音频缺帧时明确标记 discontinuity；不把缺帧两侧语音当成连续输入。

已批准的 D-06 方案：手填服务地址、共享令牌鉴权，仅用于本机/受控局域网普通 WS；首版不内置 TLS 或提供公网部署，不做自动服务发现。
令牌放在握手鉴权头，不拼入 URL、不写入日志/示例/发行包。服务端在接收音频前完成鉴权；现有配置草案的 `127.0.0.1` 不证明鉴权已实现。
普通 `ws` 未加密，音频、字幕与令牌不因鉴权而获得传输保密性；用户已同意该首版边界，TLS/WSS 需另行规划。
已确认断线自动重连建立新会话并丢弃未发送旧音频、旧结果；不回放过时字幕或恢复旧翻译上下文。
连接重试采用有界退避，可手动取消；停止期间不得自动重开会话。鉴权失败或协议不兼容提示修正配置，不重复进行自动网络重试。
断线时取消旧会话任务并清空客户端积压，重新协商且 session_started 后才恢复音频上传；迟到旧会话结果由身份校验丢弃。
可选 Linux Docker 中的 `0.0.0.0` 只是容器内监听地址，宿主端口绑定需另行审阅；Windows server 直接原生运行。

## 6. 生命周期、背压与诊断

计算状态：`uninitialized → detecting → loading → ready → failed/shutting_down`。
会话状态：`idle → starting → running → stopping → idle`，错误可进入 `failed` 并显式恢复。
服务就绪与会话运行分开，模型未加载不可报告 ready。

启动次序：校验角色配置与模型 → 检测后端与加载 → 建立会话 → 开始采音。
停止次序：禁止新输入 → 停止采音 → 取消识别/翻译 → 清会话队列 → 确认停止。
退出额外关闭服务连接、卸载模型与等待所属任务/子进程退出，超时有诊断。
已确认计算端停止会话保留模型、退出应用卸载。停止时只保留有明确归属的已加载引擎，不保留旧会话音频、上下文或在途推理/翻译任务；客户端没有模型资源。
恢复会话创建新身份并复用就绪模型，不重新加载未变更的模型/设备。设备或模型配置变化时按需重新初始化，不复用不匹配资源。
模型与引擎所有权属于计算应用，会话只拥有输入、上下文和在途任务；会话关闭不能误卸载共享模型，应用退出必须回收引擎及所属辅助进程。
停止期间的内存/显存模型驻留是已批准行为；退出后的模型驻留或辅助进程残留属于验收失败。

每条链路单独设上限：采音缓冲、网络写队列、服务音频队列、ASR 在途任务、翻译任务、事件队列、UI 历史。
本版设计采用过载明确反馈并结束当前会话，防止静默丢弃中间音频；这属于最终规划审阅内容。丢旧保新不纳入本版，若后续改动会话恢复行为，另行说明缺口与字幕重置规则。
诊断展示硬件检测、后端可用、模型加载、实际推理设备四层证据；设备选择失败按配置草案显式失败。
首轮硬件见 [验收基准](research/hardware-baseline.md)：7950X / 64 GiB / RX 9070 XT，另有 AMD 集显。
本次 Vulkan 枚举 GPU0 是集显、GPU1 是独显；配置不能把枚举顺序当成稳定身份，实际推理必须确认选中 RX 9070 XT。
已确认首轮 RX 9070 XT 优先、先验证 Vulkan；CPU 可由用户手动选择，GPU 初始化或推理失败明确报错，不静默回退至 CPU 或集显。CPU 切换须由用户手动选择。
Vulkan 仍需兼容实验，不以工具枚举成功报告后端或模型已就绪。ASR 与翻译分别报告所选后端、实际设备与加载状态。
若所选引擎/模型不支持指定独显，报告不兼容；用户明确选择 CPU 后重新初始化相关推理资源，诊断如实展示 CPU。
测量队列音频时长、推理耗时、草稿/定稿/译文到达时间、峰值内存及退出时间。
跨机器端到端延迟在客户端用本地采音与接收时刻计算，服务内耗时用服务端单调时钟，不能直接相减两台机器时间戳。
已批准 D-02c：基准固定英语、日语各 10 分钟清晰单人语音，覆盖短句/长句/静音；多人对白与背景音乐补充报告，强噪声/重叠语音不作为首版质量硬门槛。
由 C2 固定样本文件/hash、来源与参考文本，分别测量两种语言，不合并成掩盖单语种失败的总分。C6 用同一基准验证 full 与 client/server 闭环；受控样本可以用于测试，应用仍不录制用户会话或保存推理正文。测量与已批准 D-10 策略见 [基准计划](research/benchmark-plan.md)。
已批准 D-10：连续运行 60 分钟无崩溃、积压不持续增长；先取得指定模型/独显/样本的 C2 基准，再向用户审阅锁定文本质量、草稿/定稿/译文延迟、内存/显存及前台开销的发布数值门槛。C6/C7 达标才能发布，未批准或未达标不得宣称验收通过；CPU 与 Linux CPU 容器能力分别报告。

已批准 D-09：音频、原文和译文仅在当前会话内存中处理，不写入记录、缓存或临时文件；停止/重连按会话规则清理。UI 会话内历史仍有界，不提供跨会话回看或内容导出。
诊断日志采用字段白名单，仅记录状态、错误类别、设备/后端与耗时/积压等诊断指标；禁止记录音频、原文/译文、提示词、令牌或未经筛选的协议/引擎输出。
每个运行目录内日志总预算为 20 MiB（20 × 1024 × 1024 字节），覆盖应用及受管理引擎诊断，不以多个日志文件规避上限；按最旧优先轮转，写入前约束单条记录大小，重启后仍遵守总预算。
引擎输出经解析提取安全诊断字段，不将 stdout/stderr 原样持久化；验证所选引擎可以关闭内容记录与文件输入缓存。无法满足时先报告兼容实验失败，不放宽已批准的数据策略。
日志不可写或轮转失败时反馈诊断状态，不能改为保存会话内容或无限写入；模型文件与非内容型引擎缓存不计入诊断日志预算。

## 7. 桌面与平台适配

候选 egui/eframe；先用真实原型验证透明、置顶、穿透与中文字体。
设置窗独立于悬浮窗，提供停止、诊断与恢复调整模式入口。
初始禁止穿透；恢复入口通过实测之后才允许开启。
已批准 D-08：默认调整模式且不穿透；观看模式开启穿透，托盘可切回调整模式并打开设置、停止字幕或退出。
关闭设置窗只隐藏，字幕会话继续运行，不触发模型卸载；退出通过明确菜单动作执行资源回收。托盘不可用时不允许进入无法恢复的穿透状态，运行中恢复入口失效时应恢复可操作模式并反馈。
全局快捷键、开机启动和自动更新留作后续；首版不注册全局快捷键、不设置自启或自动更新任务。
字体与背景提供可读性设置，长句换行；保存位置前校验可见显示区域，处理拔掉显示器后的窗口恢复。
已批准 D-05b：默认双语，按时间顺序展示最近 3 个语句组，当前草稿/定稿计入；每组原文在上、对应译文在下，长句换行不增加语句数量。显示句数设置有界，具体 schema/上限由 C1/C5 固定。
较高 revision 替换同一组，final 不另占一组，译文只更新其所属可见组；已淘汰组的迟到译文不重新插入。停止/重连/语言切换按会话边界清理历史，不提供跨会话回看。
双语/仅原文/仅译文是同一字幕状态的显示选项；切换不改变识别/定稿翻译规则，不重复请求推理。仅译文模式隐藏原文草稿，在译文未就绪或失败时呈现状态；双语和仅原文模式继续即时展示原文。
现有部署草案 history_lines=3 的计数含义不明确，C1/C5/C7 应统一为语句组数量并同步配置 schema、示例和清单，不让视觉换行影响历史淘汰。

| 平台分支 | 候选路线 | 发布前所需证据 |
| --- | --- | --- |
| Windows | WASAPI render endpoint loopback | 真实播放采集、设备切换、透明置顶/穿透、DPI 与多屏 |
| Linux | 按音频服务与 X11/Wayland 分别研究 | 系统输出 monitor、权限、窗口协议限制；不能合并宣称支持 |
| macOS | 按最低系统版本研究系统音频 API | 权限流程、真实输出采集、窗口与计算后端 |

已确认 D-01b：Windows 首发范围为 Windows 10/11 x64，Linux/macOS 后续支持；不把 build 26100 设为最低版本。三角色采用共用 Windows x64 发行程序作为设计目标。
Windows full/server/client 均原生运行，安装、启动、推理和实机验收不依赖 Docker、Docker Desktop 或 WSL。
首轮实机为 Windows 11 IoT 企业版 LTSC build 26100；不据此宣称已兼容其他 Windows 版本。
候选 `x86_64-pc-windows-msvc` 工具链支持 Windows 10+，不等于 GUI/引擎依赖已兼容；固定依赖时检查最低系统 API 与运行库，不引入未经处理的 Windows 11 专属要求。
WASAPI 事件驱动回环在 Windows 10 1703 前有不同处理要求；采音适配器需通过兼容路径覆盖该差异，不能把 1703 默认为未经批准的最低版本。依据见 [一手资料](research/evidence.md)。
Windows 10 与 Windows 11 分别验证三角色启动、采音/窗口（full/client）、配置/连接与计算（full/server）；驱动与设备组合单独记录。缺少 Windows 10 环境时保留未验收状态，不能仅凭编译或 Windows 11 通过宣称完成。
Linux/macOS 路线仅保留适配边界，不承诺已有可用实现。Playwright 对原生窗口验收无效。
获批 UI 子任务按项目 policy 加载 UUPM 通用设计研究，不套用 React/Tailwind 技术栈。

## 8. 配置、模型与交付兼容

沿用 `deploy/PACKAGE-LAYOUT.md` 的三角色便携目录和调用者 CWD 无关的运行根目录。
角色配置经版本化 schema 解析；现有 `schema_status=draft` 不能直接视为程序已支持。
客户端拒绝推理配置；服务端不要求采音/窗口配置。错误包含字段位置和原因。
已批准 D-02b：首版源语言由用户显式选择 `en` 或 `ja`，目标为 `zh-Hans`；设置与协议能力协商只声明这两种源语言，不提供自动检测选项。
未选择源语言时提示完成设置再开始会话；`source=auto` 或不支持的语种明确报错并提示选择英语/日语，不静默推断或改写配置。
运行中切换源语言先停止旧会话、取消旧任务并清空音频/翻译上下文，再以新身份启动；模型/设备未变时复用已加载引擎，旧结果不得污染新语言字幕。
现有部署草案的 `source=auto` 是需在实现交付时更新的旧值，不代表批准能力；C7 同步原生/Docker 示例、文档及对应资产清单，当前不改 scaffold 归档。自动源语言检测留作后续。

README 指定的首轮对象：`qwen3-asr-1.7b-q4_k.gguf`、`Hy-MT2-1.8B-UD-Q3_K_XL.gguf`。
模型由用户在计算端提供，不默认下载或打包；兼容记录包含来源、revision、SHA256、模型架构、量化、引擎版本、设备与许可。
不能仅按文件名或 `.gguf` 后缀推断加载兼容。VAD 等额外资产单独列出。
当前 Windows 基准的两款模型位于 `E:\tmp\models`，实测字节大小与 SHA256 见 [模型基准](research/model-baseline.md)。
计算端模型配置支持读取外部绝对路径；便携运行目录内相对路径仍按运行根目录解析。
不把验收机盘符写成产品默认配置；客户端无需此目录，Docker 需单独映射宿主目录与容器路径。
Docker 只作为 Linux server 可选部署，模型/配置与软件分开；CPU 基线能加载不代表满足实时指标。
Windows 交付原生可执行文件和必要私有运行依赖，安装器不安装或探测 Docker/WSL 作为必需条件。
Windows 构建与验收采用原生工具链；项目在其他宿主使用的临时开发容器不成为 Windows 构建、安装或运行前置。
Linux CPU 容器与 Windows 原生 GPU 分别留下端到端证据，不把 Windows Docker GPU 纳入首版或验证矩阵。
安装器、镜像和发行包在真实程序存在之后实现，保留哈希、路径所有权、离线与用户配置保护契约。

## 9. 技术取舍与回滚

- 共用领域层防止 local/remote 字幕规则漂移；平台与引擎细节停留在适配器。
- 私有进程便于隔离引擎崩溃，但需证明常驻、就绪、取消与回收；FFI 留作实验失败后的替代。
- 不加入数据库、云账号或服务发现基础设施；首版仅持久化配置及有界安全诊断，不存储音频/字幕记录。
- 子任务以可独立验证模块交付；协议/配置变更需同步消费者、fixtures 和部署草案。
- 原型失败时只回滚该子任务拥有的文件，不动用户修改、模型、便携配置或无关 Trellis 状态。
- 尚未发布，暂不设计线上迁移；正式发布前固定协议/schema 版本和不兼容拒绝行为。
