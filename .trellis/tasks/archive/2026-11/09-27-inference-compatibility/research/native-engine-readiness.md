### CrispASR: real Windows routes, with concrete policy gaps

The fixed [release API](https://api.github.com/repos/CrispStrobe/CrispASR/releases/tags/v0.8.37) lists `crispasr-windows-x86_64-vulkan.zip`, 37,389,047 bytes, digest `sha256:de82af0b5cdb3aca9a4666ec4ac18ab1f283dd2d108c65f37eac354f9fb2088c`. It also lists a Windows Vulkan shared-library bundle and separate CPU/CPU-legacy bundles. The README's short download table omits the Vulkan zip; absence from that table is not absence from this release. Archive contents, dependent DLLs, executable version and loaded backends still need checking after any authorized acquisition.

The fixed [build-vulkan.bat](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/build-vulkan.bat#L11) uses `vswhere -latest -products * -requires ...VC.Tools.x86.x64` without a version filter, calls `vcvars64.bat`, and configures Ninja with `GGML_VULKAN=ON`, `GGML_CUDA=OFF`. Its error/docs wording mentions VS 2022, but source does not exclude the discovered VS 2026. Actual compilation with that toolset is unverified. SDK discovery checks `VULKAN_SDK` or `C:\VulkanSDK`; configure also needs CMake/Ninja discoverable in its environment. A direct x64 developer-environment CMake invocation is an equivalent candidate if bundled tools are outside PATH.

Backend aliases `qwen3` and `qwen3-1.7b` instantiate the same Qwen implementation ([backend dispatch](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/examples/cli/crispasr_backend.cpp#L160)). The registry explicitly names the approved 1.7B Q4_K asset ([registry](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/src/crispasr_model_registry.cpp#L182)). This is stronger than generic GGUF support but still not a successful Windows/RX 9070 XT run.

The [publisher card](https://huggingface.co/cstr/qwen3-asr-1.7b-GGUF/blob/674df5d44b50a63e7102a18895ed20e3f91de301/README.md) explains that this rebaked Q4_K file retains the audio tower at Q8_0; it must not be interpreted as every tensor being Q4_K. Prior exports could produce empty/repeated output while reporting success. Check real speech content and per-tensor types, not only exit code. Expected metadata namespace is `general.architecture=qwen3asr`, `qwen3asr.sample_rate=16000`, audio/LLM dimensions and GPT-2 BPE token metadata; [converter](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/models/convert-qwen3-asr-to-gguf.py#L467) and loader agree on that private namespace. Do not replace this with generic llama.cpp Qwen text-model metadata.

**GPU selection is preferential, not fail-closed.** [gpu_backend_pref.h:118–165](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/src/core/gpu_backend_pref.h#L118) can try another matching device/registry and ultimately call automatic selection after a requested device fails. [qwen3_asr.cpp:1533–1537](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/src/qwen3_asr.cpp#L1533) falls back to a CPU backend if initialization returns null. Therefore `--gpu-backend vulkan -dev N` alone is not proof of the approved device/no-fallback behavior. Resolve RX 9070 XT by current engine enumeration and physical description/identity, verify the initialized backend before reporting ready, and reject a mismatch. CPU support used for host work/unsupported graph operations must be distinguished from switching the selected compute device or running the whole engine on CPU. GPU failures cannot silently select CPU/iGPU.

### ASR stream contract and model residency limitation

At the fixed version, `--stream --stream-json` consumes binary signed PCM16 little-endian, 16 kHz mono on stdin and emits JSONL `partial`, `final`, `silence` on stdout. Partial/final carry utterance identity, text and sample-derived seconds; this is not synesthesia's session/generation/revision protocol. A fresh session must add product identity and reject old events. The documented default is a rolling 10-second window/3-second step; it is a tuning starting point, not a latency promise. Silence finalization with VAD can use speech boundaries; no-VAD mode infers silence from empty decoded output. A bounded utterance redecode makes final text a separate computation, and optional VAD/punctuation assets require explicit inventory. [Fixed streaming guide](https://github.com/CrispStrobe/CrispASR/blob/v0.8.37/docs/streaming.md).

Windows stdin is explicitly switched to binary mode; the loop uses blocking `fread`, and EOF closes it ([run.cpp:4084](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/examples/cli/crispasr_run.cpp#L4084), [4197](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/examples/cli/crispasr_run.cpp#L4197)). EOF may redecode and emit an outstanding final before returning from the stream command ([4834–4900](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/examples/cli/crispasr_run.cpp#L4834)). Consequences:

- Closing stdin or killing/relaunching this CLI does not preserve the already loaded model across stop/resume.
- Leaving stdin open and ceasing writes can preserve the process/model but also preserves rolling audio/utterance state, cannot change language arguments, and does not interrupt an in-flight decode. Sending silence is continued processing, not compliant stopped state.
- The inspected Qwen public header and CLI adapter provide no exposed abort/cancel callback for in-flight Qwen encode/prefill/decode. KV reset is not cancellation. Dropping results alone prevents stale subtitles but does not satisfy cancellation/no-old-work/no-old-context.
- Qwen's optional realtime-session path exposes reset and is selected for an R2T2 recipe or explicit environment opt-in; stock Qwen3-ASR is not thereby a proven incremental encoder. Do not enable that different schedule merely to make lifecycle tests pass.

Sources: [Qwen public API](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/src/qwen3_asr.h), [adapter init/forced language](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/examples/cli/crispasr_backend_qwen3.cpp#L61), [reset/optional realtime creation](https://github.com/CrispStrobe/CrispASR/blob/d08ec2dd83411a8389745c97c4f2e3955e084280/examples/cli/crispasr_backend_qwen3.cpp#L937). Explicit `-l en`/`-l ja` produces forced-language assistant prefill in this adapter; avoid auto-language/model aliases that fetch unrelated assets.

The unmodified stdin CLI is suitable for a first compatibility smoke experiment but insufficient as the complete product adapter. A controlled helper retaining a Qwen context, a private service, or FFI must prove session-state destruction/recreation independently of engine ownership, an interruptible or demonstrably bounded decode, fail-closed device selection and controlled shutdown. Existing C ABI bindings alone do not establish those properties. No route is selected here, and no external private service is started.

### Hy-MT2 UD: expectations for llama.cpp Windows Vulkan

The exact [Tencent config](https://huggingface.co/tencent/Hy-MT2-1.8B/blob/9a341cd1b679d3efd23b46e847b01745a71ed792/config.json) declares `HunYuanDenseV1ForCausalLM`, hidden size 2048, 32 layers, 16 attention heads/4 KV heads, head dimension 128, QK normalization and vocabulary 120818. llama.cpp's fixed [conversion/hunyuan.py:157](https://github.com/ggml-org/llama.cpp/blob/7fe450e19305b828c199d602c23a8337aaa1f03b/conversion/hunyuan.py#L157) maps this class to `HUNYUAN_DENSE`. Expected GGUF architecture is `hunyuan-dense`, not Qwen3 or a generic Llama. Verify local architecture/dimensions, tensor names/types, tokenizer pretokenizer, BOS/EOS/EOT and embedded chat template; a mismatch is a blocker, not a reason to override metadata or change the approved model.

The fixed [upstream template](https://huggingface.co/tencent/Hy-MT2-1.8B/blob/9a341cd1b679d3efd23b46e847b01745a71ed792/chat_template.jinja) uses Hy-specific user/assistant and sentence-boundary tokens. Its raw UTF-8 size (654 bytes) and SHA256 (`b7491ec0e9c869dfce20f2176758099bf248d979dd05530ede99deb21698acee`) exactly match the local GGUF template fingerprint reported by the root agent. Use this embedded template with Jinja and test rendering; do not assume ChatML. Prompt the requested Simplified Chinese translation as one user message; no default system prompt is required. The [Unsloth card](https://huggingface.co/unsloth/Hy-MT2-1.8B-GGUF/blob/0378cc2780f462f0fd397d0cdd244d2f769de40e/README.md) identifies the Tencent base model and UD quantization publisher. Check the actual tensor-type distribution: `UD-Q3_K_XL` is a publisher preset, not a new GGML tensor enum. The fixed [Vulkan implementation](https://github.com/ggml-org/llama.cpp/blob/7fe450e19305b828c199d602c23a8337aaa1f03b/ggml/src/ggml-vulkan/ggml-vulkan.cpp#L5273) handles `Q3_K` and other K-quant types; this does not prove every tensor/operation/device combination in this file.

This is also confirmed beyond converter registration: [llama-arch.cpp:122](https://github.com/ggml-org/llama.cpp/blob/7fe450e19305b828c199d602c23a8337aaa1f03b/src/llama-arch.cpp#L122) names the architecture, [models.h:2101](https://github.com/ggml-org/llama.cpp/blob/7fe450e19305b828c199d602c23a8337aaa1f03b/src/models/models.h#L2101) shares the Hunyuan VL loader/graph, and [hunyuan-vl.cpp:3–51](https://github.com/ggml-org/llama.cpp/blob/7fe450e19305b828c199d602c23a8337aaa1f03b/src/models/hunyuan-vl.cpp#L3) handles 2048-hidden 1.8B, Q/K norm tensors and tied output embeddings. Actual complete tensor names/shapes and graph execution remain unverified.

The Tencent generic GGUF card mentions STQ/custom-kernel support and uses CPU commands. That statement must not be generalized to this fingerprint-matched Unsloth UD file or treated as Windows Vulkan evidence. No special STQ dependency is asserted without inspecting local tensor types.

[Fixed llama.cpp build guide](https://github.com/ggml-org/llama.cpp/blob/7fe450e19305b828c199d602c23a8337aaa1f03b/docs/build.md#L357) documents native Windows Vulkan source builds using CMake and SDK shader tools/headers. MSVC/Ninja in the discovered developer environment is a candidate route. Enumerate with `--list-devices`, pass the actual RX 9070 XT device name through `--device`, request GPU layers, and check loaded/offloaded buffers. Do not hardcode enumeration index from `vulkaninfo`; llama.cpp and CrispASR identifiers are different contracts.

For a managed localhost llama-server, the fixed sources provide request cancellation and retained model ownership: [server-queue.cpp:602](https://github.com/ggml-org/llama.cpp/blob/7fe450e19305b828c199d602c23a8337aaa1f03b/tools/server/server-queue.cpp#L602) posts priority cancel tasks; [server-context.cpp:2454](https://github.com/ggml-org/llama.cpp/blob/7fe450e19305b828c199d602c23a8337aaa1f03b/tools/server/server-context.cpp#L2454) releases the matching slot. Idle sleep explicitly destroys/reloads model state; keep `--sleep-idle-seconds -1` for approved model residency ([arg.cpp:3806](https://github.com/ggml-org/llama.cpp/blob/7fe450e19305b828c199d602c23a8337aaa1f03b/common/arg.cpp#L3806)). HTTP client cancellation must be shown to reach this path during streaming/non-streaming requests; cancellation latency is unmeasured. Separate context-cache cleanup from model retention; do not enable prompt/slot disk saving or raw request logging. Bind explicitly to loopback, own process cleanup, and keep private HTTP separate from product LAN WS. Source support is not lifecycle acceptance.

### Smallest meaningful next experiment, after C2 activation

1. Recheck both local file fingerprints; extend the already completed selected-metadata check to tensor tables/types without modifying weights. A reviewed bounded reader or fixed `gguf-py` inspection tool can do this; Python is only an optional experiment dependency, not a product runtime. 2. Acquire/verify the pinned CrispASR Windows Vulkan archive in a task-owned tools directory, or prepare the pinned native source build. 3. Use two short authorized English/Japanese PCM16/16 kHz mono samples with expected speech and a silence interval. Require nonempty plausible content, coherent partial/final/time identity, clean output channel, EOF behavior, and actual selected GPU. No VAD auto-download: start with documented no-VAD limitations or explicitly inventory a chosen VAD asset before acquiring it.
4. Load the exact UD model with native llama.cpp on RX 9070 XT; verify template, run one English and one Japanese final sentence to Simplified Chinese, inspect output/stopping and device/offload evidence. Start with bounded context/output and one request; record cold/warm latency and RAM/VRAM. Request cancellation then a fresh unrelated sentence must demonstrate no previous-session context or continuing generation. 5. Before calling the adapters ready, resolve CrispASR's stdin cancellation/reset/residency gap via a focused helper/FFI/private-service experiment, including stop during encode/prefill/decode, language change and restart on the same loaded model. Optional ffmpeg is a preparation tool if samples need resampling; no product microphone/system-capture dependency is inferred from it.

## Caveats / Not Found

- No SSH, remote changes, downloads saved to disk, installs, builds, model loads or GPU runs were performed by this researcher. Public HTTP metadata/source text was read in memory. A sandbox DNS failure was followed by approved read-only network access; no approval rejection occurred.
- Native Windows Vulkan packages/source paths exist; neither engine nor model has passed the actual RX 9070 XT experiment. Windows 10 remains in approved scope and is untested.
- Rust is absent from the probed standard Windows account path; SDK standard-path discovery failed. These are preparation gaps, not proof those tools exist nowhere. Native C++ tool files are present but not compiler-smoke-tested.
- Plain CrispASR stdin has concrete lifecycle/device-policy gaps. Hiding late output or killing/reloading the model cannot be presented as satisfying approved stop/resume residency.
- Selected GGUF metadata is recorded in the root-agent report and the Hy template hash matches the fixed base template. Complete tensor tables, actual mixed quant types and complete license text still need recording. Matching LFS hash resolves published content identity only. No substituted models or silent fallback are proposed.
- Model throughput, cancellation bounds, simultaneous ASR/translation contention, translation quality and D-10 numeric release thresholds remain unmeasured. No performance guarantee is inferred from file size, Vulkan enumeration, release availability or another publisher's benchmark.
