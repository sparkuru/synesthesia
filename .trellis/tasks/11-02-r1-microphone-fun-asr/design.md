# R1 运行设计

状态：待最终计划确认；本文件描述拟实现合同，不表示接口或原生能力已经存在。源码与官方服务依据见 [运行研究](research/runtime-plan.md)。

## 模块和资源所有权

- `core`：继续拥有 InputId/UtteranceId、SourceEvent、唯一 SubtitleReducer、清屏高水位和纯状态/预算规则；不接触密钥、设备或网络。
- `audio`：增加 Windows capture endpoint 麦克风适配，复用已有格式检查、重采样与 AudioChunk。旧回环入口保持兼容；新增“停采后排空”路径与旧取消/清空路径分开。
- 真实 Fun-ASR 适配实现出现时再增加相应模块/包，负责厂商协议、鉴权、端点、事件归一化和有界传输；不得使用旧 WS v1 codec 假装云协议。
- `desktop`：拥有原生窗口及 core 状态的借用呈现；显式表达 Disabled 翻译，不新建字幕 reducer 或启动翻译。
- `apps/synesthesia`：拥有采集、识别、窗口和会话任务的实际编排；R1 不构造 NativeInference 或本地模型。GUI 线程不执行阻塞网络/资源 join。

旧 Session 在每个 final 排翻译、Stop 取消清空，云发送又没有旧 ASR 逐帧完成语义，不能直接套用。优先提取可复用纯逻辑并增加识别独立运行策略；保留旧构造/协议行为及原测试，避免复制整套领域状态。

## 入口与配置边界

拟新增 `synesthesia --run FILE` 打开真实应用；保留无参数帮助及 `--check-config FILE` 的原行为。窗口启动不等于上传，用户 Start 后才读本机密钥、连接所选云任务，就绪后开麦。

R1 runtime 只接受 microphone + fun_asr + translation disabled + source_only。其他 schema 2 组合仍可结构检查，但运行时明确报告本轮不支持；不静默换组合。不改变 schema 1 的路径/语言等含义。

端点由配置确定一次：workspace_id 有值时校验为合法 DNS 标签，使用所选地域的专属域名；缺省时按官方仍有文档依据的北京/新加坡公共域名映射。具体映射及来源在研究中。握手失败不换地域、模型、域名或处理方式；若真实账户需要 workspace，在运行就绪阶段报安全配置错误，结构检查不联网。

## 识别协议与归一化

按照研究中的官方启动/结束流程：连接、run-task、task-started、上传 PCM、finish-task、接收末尾结果、task-finished、关闭。不能把 WebSocket 写入成功当成服务端逐帧 ASR 完成确认。

以下是本项目适配合同，实施时先用受控事件 fixture 固定：

- 本地会话/输入代际与云 task_id 绑定，每个有效服务 sentence_id 映射到单调本地 utterance 身份与版本；错 task_id、旧代际、心跳、空句首不能直接发布为字幕。
- 非空草稿的未知结束时间以已知句首的零长度采样范围表示下界；有真实 word/end 时间后扩展。16 kHz 下 ms→sample 使用检查过的整数转换，不用当前上传进度猜语音结束时间。单句起点固定、结束不倒退；若有效服务事件与此不符，先固定证据并调整 v2 合同，不能在 UI 隐藏冲突。
- `sentence_end` 标记 final；R1 保留终态 final、重复去重与迟到草稿拒绝。对同一句不同内容的第二个 final 反馈可见协议/能力错误；没有官方或真实证据时不放宽旧 WS v1 的 final 规则。未来合法修订另定义 v2 版本/译文失效语义。
- 清屏继续识别，且把适配器已分配但尚未显示的句子也纳入高水位，避免空句首之后的迟到文本复活。仅维护有界当前/可见身份与高水位，不无限累积映射。
- `sentence_silence_ms` 显式映射为服务断句参数；源语言按所选模型能力检查。context 单字符串映射为官方 user/input_text 结构，不自动保存对话历史；不支持 context 的模型或无法兑现的非空参数在启动前明确失败，不能静默忽略。
- 为持续静音采用官方 heartbeat 参数并验证超时行为；这是同一任务保活，不是自动重连或补播。外来错误只映射为安全类别，不回显原始消息或正文。

## 生命周期、预算和停止

拟定状态：Idle → Preparing → Running → Draining → Stopped；失败/超时进入 Cancelling → Failed。Start/Stop/退出的重复操作幂等，显式重新开始分配新会话。

正常 Stop：停止接收新设备输入，按截止边界处理此前已接受的原始/规范化尾帧，排空有界发送队列，发 finish-task，在有限 deadline 内继续接收/归约末尾结果，收到 task-finished 后关连接并释放资源。字幕可保持可见；本轮不借旧 stop 的清空动作伪装正常收尾。

故障/超时取消：立即停止新采集/上传，取消剩余拥有权，释放所属连接/线程/任务，并显示最后结果可能不完整。停止完成后旧事件一律无效；不能只关闭窗口或丢弃句柄。

以现有 16 kHz mono PCM16、单帧最多 3200 samples、音频 32000 samples/100 frames、发布 64 项及文本边界为起点。明确采集→规范化→发送→在途的总预算与拥有权转移；网络队列不得另加无界缓存。超时与 join deadline 在首个技术验证门锁定具体值并测试，它们是工程预算，不是对外延迟指标。

## 窗口和技术验证门

原生窗口包含原文字幕、Start/Stop、清屏、字号/视觉行数与可靠设置恢复；支持移动/调整、换行和可见错误。历史句数与视觉行数独立。恢复控制留在可访问窗口中，R1 不进入不可恢复的穿透状态，也不要求托盘。

真实框架/renderer/版本尚未锁定。实施起点先按本地 UUPM 与 Rust 1.90 约束，做 Windows 11 透明置顶、字体、DPI、焦点和恢复控制的最小原型；验证通过后将具体依赖、签名和证据补到 design/JSONL，再接主链。旧 C5 仅为候选研究，不作为新批准。若技术方案必须改变产品行为或平台范围，返回规划。

## 验证与回退

离线层用假时钟、受控传输与无敏感正文 fixture 覆盖识别就绪门、Disabled、队列拥有权、空/重复/迟到事件、清屏、停止尾帧与 deadline。受控 WebSocket 对端验证协议但不等于云验收。Windows 原生验证麦克风、窗口及资源；真实云只用用户本机凭据。

每个里程碑保留可运行的先前入口及测试；无法通过原型/真实设备门时不宣称支持或自动换后端。R1 只声明实际验收组合，完整发行门槛留给 R5。
